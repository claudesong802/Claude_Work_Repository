# 구름 덮개 설계

결정 출처:
- 사용자 10-18 밤: 첫 접속 · 새로고침 로딩 덮개 · 최소 사양 iPad mini 6 Chrome · 클라우드 세션에서 처음부터 구성.
- 사용자 10-19: 손그림 구름 PNG 6장(`assets-src/clouds`)을 그대로 쓰고, 영상(cloud-seoul-v3.mp4)의 「구름을 뚫고 내려가는」 움직임으로 펴지며, 걷히면 실제 지도가 나옴. 구름을 코드로 그리던 방식과 선 그리기 장면은 걷어냄.
- 사용자 10-19: 하늘 결은 (다) 16 장 · 중간 크기 · 0.6 초를 기본으로 하고, (가) · (나)를 `?sky=` 로 견줌.
- 관리자: 시안 a · b · c 의 펴지는 꼴 · 빈틈 시험 · 그림 풀리기 전 흰 바탕 · 진단 창.

본보기 그림은 `docs/reference/cloud-style.png` 입니다. 영상은 움직임 본보기일 뿐 저장소에 넣지 않았고, 화면에도 싣지 않습니다(서울 일러스트 · 「서울」 글씨 포함).

## 영상에서 읽은 움직임(1920×1080 · 30 fps · 6 초 · 0.2 초 간격으로 뽑아 봄)

| 영상 | 모습 | 우리 화면 |
| --- | --- | --- |
| 0 ~ 0.6 초 | 구름이 빈틈없이 덮은 채 아주 조금 흐름 | 기다림: 덮은 채 천천히 흐름(되풀이) |
| 0.8 초 | 정확히 가운데에 작은 구멍이 열림 | 펴지기 0 ~ 25 %: 가운데 구름이 커지며 녹음 |
| 1.0 초 | 구멍이 화면 대부분으로 · 구름은 커지며 가장자리로 | 펴지기 50 % |
| 1.2 초 | 다 걷힘 | 펴지기 100 % — 덮개가 DOM 에서 빠짐 |

영상의 펴지기는 0.4 ~ 0.5 초입니다. 펴지기 길이는 하늘 결마다 따로 둡니다(아래 표).

## 장면

| 장면 | 언제 | 길이 | 움직이는 속성 |
| --- | --- | --- | --- |
| 흰 바탕 | 덮개가 뜬 때 ~ 구름 그림이 다 풀린 때(`img.decode()`) | 그림 받는 시간(늦어도 1.2 초) | 없음 — 처음부터 불투명해 지도가 먼저 비치지 않음 |
| 구름 띄우기 | 그림이 다 풀린 때 | 0.22 초 | `opacity` |
| 기다림 | 준비 신호까지 | 로딩 시간(구름이 뜬 뒤 최소 0.6 초) | 구름마다 1 vmax 안 이동 · 크기 1.00 ~ 1.03(7 ~ 11 초 주기 · 되풀이) — `transform` |
| 펴지기 | 준비 신호(또는 상한) 뒤 | 하늘 결마다 0.5 · 0.6 · 0.8 초 고정 | `transform` · `opacity` 만 |
| 사라짐 | 펴지기 끝 | — | DOM 에서 빠짐(지도 터치를 막지 않음) |

- **최소 보임 0.6 초**는 구름이 뜬 때부터 셉니다. 흰 바탕만 잠깐 보이고 바로 걷히는 깜빡임을 막기 위해서입니다. 상한(15 초)은 그림과 상관없이 덮개가 뜬 때부터 셉니다.
- **그림 기다림 상한 1.2 초**: 그림이 끝내 안 오면(오프라인 · 막힘) 기다리지 않고 시간을 흘립니다.
- **같은 창 두 번째** · **동작 줄이기**는 그림을 기다리지 않습니다. 그림은 이미 받아 두었거나 쓰지 않기 때문입니다.

## 펴지기 시안(`?design=`)

| 시안 | 꼴 |
| --- | --- |
| a 영상 그대로 | 화면 가운데 구름이 앞 45 % 안에 2.6 배로 커지며 사라짐(가운데 구멍). 나머지 구름은 가운데에서 멀수록 늦게(최대 펴지기 길이의 30 %) 출발해 2 배로 커지며 화면 중심에서 바깥으로 80 vmax 밀려남. 가속(cubic-bezier(0.32, 0, 0.6, 0.5) — 절반 시점에 35 % 진행) |
| b | a 에 더해 밑의 지도가 1.04 → 1 로 살짝 다가옴(내려앉는 느낌). 지도 컨테이너의 `transform` 이라 덮개 밖의 몫이며, `onPartStart(partMs)` 로 같은 때 시작 |
| c | 가로 띠마다 좌우로 엇갈려 흘러나감(짝수 띠는 왼쪽 · 홀수 띠는 오른쪽 · 가운데 띠부터) |

흰 바탕은 펴지기 앞 40 % 동안 `opacity` 로 사라집니다. 그래서 가운데 구멍으로 지도가 먼저 보입니다.

## 하늘 결(`?sky=` · 사용자 (다) 결정)

| 하늘 결 | 구름 | 크기(vmax) | 펴지기 | 빈틈 최대(chromium 에서 잰 값 · 6 화면비) | 구름 레이어(iPad mini · 배율 2) |
| --- | --- | --- | --- | --- | --- |
| dense (가) 영상에 가깝게 | 22 장 | 28 ~ 49 | 0.5 초 | 0.085 % | 약 54 MB |
| **mid (다) 기본** | 16 장 | 32 ~ 58 | 0.6 초 | 0.057 % | 약 54 MB |
| sparse (나) 크게 | 14 장 | 40 ~ 72 | 0.8 초 | 0.032 % | 약 64 MB |

- **그림 해독 메모리**: 6장 모두 약 25.5 MB(667 만 화소 × 4 바이트)입니다. 같은 그림을 여러 번 써도 해독은 한 번입니다.
- **합 어림**: 그림 25.5 MB + 구름 레이어 54 ~ 64 MB = **약 80 ~ 90 MB**. 레이어는 펴지기 동안 2 배로 커져도 합성 단계에서 확대만 하고 다시 그리지 않는다고 보았으며, 이는 iPad 실기에서 확인할 몫입니다.
- **자산**: WebP 6장 합 518 KB(투명 유지 · 안쪽 알파 250 ~ 254 를 255 로 · 긴 변 최대 1600 · q82). 덮개 첫 묶음(73 KB gzip)과 함께 같은 출처에서 받습니다.
- **배치**는 `scripts/cloud-layout.py` 가 찾았습니다. 그림의 실제 알파로 iPad 가로 · 세로 · 폰 가로 · 세로 · 데스크톱 · 넓은 데스크톱(21 : 9)에서 빈틈을 재고, 기다림 흐름의 양 끝에서도 잽니다. 담금질로 고르며, 같은 그림은 30 % 넘게 떨어뜨리고 뒤집기 · 돌리기를 다르게 둡니다. 쓴 인자는 다음과 같습니다.

  | 하늘 결 | 인자 |
  | --- | --- |
  | dense | `--count 22 --w-min 28 --w-max 48 --center-w-max 38 --iters 10000 --seed 23` 뒤 오른쪽 아래 · 왼쪽 빈틈 세 장을 조금 키움 |
  | mid | `--count 16 --w-min 32 --w-max 58 --center-w-max 46 --iters 8000` |
  | sparse | `--count 14 --w-min 40 --w-max 72 --center-w-max 56 --iters 8000` |

- **빈틈 문턱 0.1 %**: e2e 「빈틈」 이 흰 바탕을 숨기고 밑을 자홍색으로 칠해 찍은 뒤, 자홍색 화소 비율을 잽니다. 남는 것은 구름 가장자리 반투명 화소 몇 개(iPad 가로에서 수백 화소)라 흰 바탕 위에서는 눈에 띄지 않습니다. 구름 세 장을 빼면 이 시험이 잡습니다(뮤테이션).

## 갈래

| 갈래 | 판정 | 모습 |
| --- | --- | --- |
| 첫 접속(full) | sessionStorage 표시 없음 | 흰 바탕 → 구름 띄우기 → 기다림 → 펴지기 |
| 같은 창 두 번째(short) | `cloudcover-seen = 1` | 구름이 곧바로 덮은 채 시작 · 최소 보임 없음 · 펴지기 0.3 초 |
| 동작 줄이기(reduced) | `prefers-reduced-motion: reduce`(두 번째보다 먼저) | 구름 없음 · 흰 덮개가 0.2 초 사라지기만 |
| 서버 준비 중 | `note` prop | 덮개 아래 작은 글씨(흰 알약 바탕) · 펴질 때 같이 사라짐 |
| 상한 | 준비 신호 없이 `capMs`(기본 15 초) | 그냥 편다 · `data-reason="cap"` |

표시는 펴지기가 시작될 때 씁니다. 읽기 · 쓰기는 모두 `try` 로 감싸, 저장소가 막혀 있어도 화면은 정상입니다.

### 상한 15 초의 까닭(잠정)

- 이 세션 컨테이너(GPU 없음 · 소프트웨어 WebGL)에서 시연 지도 idle 까지 걸린 시간은 chromium 약 2.3 ~ 3.7 초, webkit 약 2.8 ~ 8 초였습니다. 가장 느린 값의 두 배 가까이를 두었습니다.
- 15 초 넘게 구름만 보이면 사용자는 멈춘 것으로 봅니다. 본 프로젝트의 서버 재시작 직후(/api 503) 길이는 iPad 실기에서 잰 뒤 확정합니다.

## iPad(WebKit)에서 부드럽게

- **레이어**: 구름 조각마다 레이어 하나(`will-change: transform, opacity`)에 CSS 애니메이션 하나씩입니다. 기다림 · 펴지기 모두 합성 단계에서 돌아, 메인 스레드가 지도 그리기로 막혀도 끊기지 않습니다.
- **쓰지 않은 것**: SVG 필터 · blur · backdrop-filter · mask · 화면 전체 Canvas · WebGL · 바깥 글꼴 · CDN. 앞 시안에서 쓰던 `stroke-dashoffset` 그리기와 mask 쓸기는 이번에 없앴습니다(메인 스레드 애니메이션이 하나도 없음).
- **진단 창(`?debug=1`)**: 펴지기 중 프레임 수 · 가장 긴 간격 · 50 ms 넘은 프레임 수 · 지도 idle · 준비 · 펴지기 시작 → 끝 · devicePixelRatio 를 보여 줍니다.
  - 시작 · 끝 시각은 `data-phase` 변화로 잽니다. 메인 스레드가 막혀 `requestAnimationFrame` 이 한 번도 안 돌아도 놓치지 않습니다(이 컨테이너의 webkit 에서 실제로 0 번이었음).
  - 진단 창에는 다음 한 줄을 적어 두었습니다.

> 프레임 간격은 메인 스레드 기준 — transform · opacity 펴지기는 합성 단계라 숫자가 나빠도 눈엔 부드러울 수 있음 · 판정은 눈이 먼저
