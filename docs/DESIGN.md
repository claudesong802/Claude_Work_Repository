# 구름 덮개 설계

결정 출처:
- 사용자 10-18 밤: 첫 접속 · 새로고침 로딩 덮개 · 최소 사양 iPad mini 6 Chrome · 클라우드 세션에서 처음부터 구성.
- 사용자 10-19: 손그림 구름 PNG 6장(`assets-src/clouds`)을 그대로 쓰고, 영상(cloud-seoul-v3.mp4)의 「구름을 뚫고 내려가는」 움직임으로 펴지며, 걷히면 실제 지도가 나옴. 구름을 코드로 그리던 방식과 선 그리기 장면은 걷어냄.
- 사용자 10-19: 하늘 결은 (다) 16 장 · 중간 크기 · 0.6 초를 기본으로 하고, (가) · (나)를 `?sky=` 로 견줌.(→ 아래 영상 방식 선택으로 견줌은 걷고 (다) 배치만 남김)
- 관리자: 시안 a · b · c 의 펴지는 꼴 · 빈틈 시험 · 그림 풀리기 전 흰 바탕(→ 10-19 흐린 미리보기로 바꿈) · 진단 창.
- 사용자 10-19: 사용자가 준 투명 PNG 연속 이미지로 만든 영상 덮개(`VideoCloudCover`)를 견줌 → 「영상 방식이 좋은거 같네」 — 영상 방식을 기본이자 공개 덮개로 정함.
- 사용자 10-19: 동작 줄이기는 B+(구름은 보이되 흐름 없이 · 조금만 벌어지며 옅어짐) · 그 갈래의 첫 흰 화면 0.3 초는 「없앰」(흐린 미리보기).
- **10-19 영상 방식 선택으로 걷음**: 펴지기 시안 a · b · c(`?design=`) · 하늘 결 dense · mid · sparse 견줌(`?sky=`) · 그리는 방식 고르기(`?engine=`) · PNG 첫 접속 덮개(흐름 · 터짐 · 큰 펴짐) · 시안 b 의 지도 다가옴. **남긴 것**: 하늘 mid 배치 하나와 시안 a 의 방향(가운데부터 · 화면 중심에서 바깥으로) — 동작 줄이기 덮개(`CloudCover`)가 쓴다.

본보기 그림은 `docs/reference/cloud-style.png` 입니다. 영상은 움직임 본보기일 뿐 저장소에 넣지 않았고, 화면에도 싣지 않습니다(서울 일러스트 · 「서울」 글씨 포함).

## 영상에서 읽은 움직임(1920×1080 · 30 fps · 6 초 · 0.2 초 간격으로 뽑아 봄)

| 영상 | 모습 | 우리 화면 |
| --- | --- | --- |
| 0 ~ 0.6 초 | 구름이 빈틈없이 덮은 채 아주 조금 흐름 | 기다림 영상(2.4 초 · 되풀이) |
| 0.8 초 | 정확히 가운데에 작은 구멍이 열림 | 걷힘 영상 시작 |
| 1.0 초 | 구멍이 화면 대부분으로 · 구름은 커지며 가장자리로 | 걷힘 영상 중간 |
| 1.2 초 | 다 걷힘 | 걷힘 영상 0.53 초쯤 구름이 다 빠짐 · 0.8 초 끝에 덮개가 DOM 에서 빠짐 |

이 움직임은 이제 사용자가 준 투명 PNG 연속 이미지(기다림 72 · 걷힘 24 장)를 그대로 영상으로 만든 것이 그립니다. 동작 줄이기 덮개는 그 방향(가운데부터 · 바깥으로)만 작게 따릅니다.

## 장면(영상 덮개 · 첫 접속)

| 장면 | 언제 | 길이 | 보이는 것 |
| --- | --- | --- | --- |
| 흰 바탕 · 첫 장면 그림 | 덮개가 뜬 때 → 첫 장면 그림(`poster.webp`)이 풀리거나 기다림 영상이 돌기 시작한 때 | 그림 받는 시간(늦어도 1.2 초) | 처음부터 불투명해 지도가 먼저 비치지 않음 |
| 기다림 | 준비 신호까지 | 로딩 시간(첫 장면이 뜬 뒤 최소 0.6 초) | 기다림 영상 한 바퀴 2.4 초 되풀이 |
| 잇기 | 준비 신호(또는 상한) 뒤 | `switch=loop`(기본) 한 바퀴 끝까지 최대 2.4 초 + 여유 0.3 초 · `now` 곧바로 | 기다림 끝 프레임 = 걷힘 첫 프레임이라 이음매가 안 보임 |
| 걷힘 | 걷힘 영상이 실제로 돌기 시작한 때(`data-swapped`) — 그때 밑의 바탕 · 첫 장면 · 기다림을 한 번에 걷음 | 0.8 초 | 걷힘 영상 — 구름이 빠진 자리가 진짜 투명이라 지도가 그대로 드러남 |
| 사라짐 | 걷힘 영상 `ended` · 늦어도 걷힘 길이 + 1.5 초 | — | DOM 에서 빠짐(지도 터치를 막지 않음) |

- **최소 보임 0.6 초**는 첫 장면이 뜬 때부터 셉니다. 상한(15 초)은 덮개가 뜬 때부터입니다.
- **영상을 못 틀 때**(저전력 모드는 자동 재생을 막음 · 형식을 못 읽음): 첫 장면 그림이 0.45 초 동안 1.12 배로 커지며 사라집니다(`data-fallback` · `transform` · `opacity` 만).

## 동작 줄이기 덮개(CloudCover · 내부 덮개)

`VideoCloudCover` 가 동작 줄이기에서만 넘기는 PNG 조각 덮개입니다. 손그림 구름 PNG 6장으로 하늘 mid 배치(16 장 · 32 ~ 58 vmax)를 깝니다.

| 장면 | 언제 | 길이 | 움직이는 속성 |
| --- | --- | --- | --- |
| 구름 띄우기 | 덮개가 뜬 때 — 코드에 든 흐린 미리보기(`cloudblur.ts` · 긴 변 200 px WebP data URL · 6장 34 KB)로 곧바로 | 0.22 초 | `opacity` |
| 선명해짐 | 선명한 그림(`assets/*.webp`)이 다 풀린 때(`img.decode()` · `data-sharp`) | 0.2 초 | `opacity`(흐린 그림 위에 겹쳐 나타남) |
| 기다림 | 준비 신호까지(최소 0.4 초) | 로딩 시간 | 없음 — 흐르지 않음 |
| 줄인 펴짐 | 준비 신호(또는 상한) 뒤 | 0.6 초 | `transform` · `opacity` 만 — 가운데 구름부터(멀수록 최대 펴지기 길이의 15 % 늦게) 화면 중심에서 바깥으로 80 vmax 의 6 % 이동 · 크기 1.05 까지 · 옅어짐 |
| 사라짐 | 펴짐 끝 | — | DOM 에서 빠짐 |

- **흐린 미리보기 먼저**(사용자 10-19 「없앰 방식으로」): 전엔 선명한 그림 6장을 다 풀 때까지(약 0.3 초) 흰 바탕만 보였습니다. 대가: 첫 묶음 JS 가 gzip 76 → 103 KB(base64 는 압축이 안 됨). 흐린 그림만 떠 있을 때의 빈틈은 최대 0.099 %(mid · iPad 가로 · 10-19 다시 잼) · 문턱 0.3 %(`sky.spec`) — 기다리는 동안은 흰 바탕이 뒤에 있어 지도가 비치지 않습니다. 선명한 그림이 끝내 안 오면 흐린 구름 그대로 펴집니다.
- **그림 해독 메모리**: 6장 모두 약 25.5 MB(667 만 화소 × 4 바이트)입니다. 같은 그림을 여러 번 써도 해독은 한 번입니다. 구름 레이어(iPad mini · 배율 2)는 약 54 MB 로 어림했습니다.
- **자산**: WebP 6장 합 518 KB(투명 유지 · 안쪽 알파 250 ~ 254 를 255 로 · 긴 변 최대 1600 · q82). 이 덮개가 뜰 때 받기 시작하므로 영상 덮개를 보는 보통 사용자는 받지 않습니다.
- **배치**는 `scripts/cloud-layout.py --count 16 --w-min 32 --w-max 58 --center-w-max 46 --iters 8000` 이 찾았습니다. 그림의 실제 알파로 iPad 가로 · 세로 · 폰 가로 · 세로 · 데스크톱 · 넓은 데스크톱(21 : 9)에서 빈틈을 재고, 담금질로 고르며, 같은 그림은 30 % 넘게 떨어뜨리고 뒤집기 · 돌리기를 다르게 둡니다.
- **빈틈 문턱 0.1 %**: e2e 「빈틈」 이 흰 바탕을 숨기고 밑을 자홍색으로 칠해 찍은 뒤, 자홍색 화소 비율을 잽니다. 잰 최대 0.078 %(iPad 가로 · 10-19). 남는 것은 구름 가장자리 반투명 화소 몇 개라 흰 바탕 위에서는 눈에 띄지 않습니다.

## 갈래

| 갈래 | 판정 | 모습 |
| --- | --- | --- |
| 첫 접속(full) | sessionStorage 표시 없음 | 영상 덮개 — 첫 장면 그림 → 기다림 영상 → 바퀴 끝에서 걷힘 영상 |
| 같은 창 두 번째(short) | `cloudcover-seen = 1` | 기다림 영상 없이 곧바로 걷힘 영상을 1.6 배 빠르게(약 0.5 초 · 걷힘 영상 ended 가 없어도 안전 시간 약 2.0 초 안에 걷힘) · 최소 보임 없음. 걷힘 길이는 실제로 트는 영상 길이가 정본 — 전엔 `timingFor("short")` 의 0.3 초가 `onPartStart` · 안전 시간(1.8 초)으로 가 어긋났다(10-19 고침) |
| 동작 줄이기(reduced) | `prefers-reduced-motion: reduce`(두 번째보다 먼저) | 구름 첫 장면을 보임(흐름 없음) · 최소 0.4 초 · 준비되면 가운데 구름부터 조금만 바깥으로 벌어지며 옅어짐(이동 = 첫 접속 펴짐의 6 % · 크기 1.05 까지 · 0.6 초) — B+(사용자 10-19 「권장하는 방향대로」). 영상 덮개는 이 갈래를 구름 조각 덮개(`CloudCover`)로 넘긴다. 경위: 처음엔 구름 없이 흰 화면 0.2 초 → 사용자 iPad 가 이 설정이라 구름이 안 보임 → B안(제자리에서 옅어지기만) → 「펴짐」 이 안 보여 B+. e2e 가 「작게」(중심 이동 0.5 % ~ 화면 긴 변 10 % · 크기 < 1.1)를 잰다 — 첫 접속이 영상이 되어 「크게」 대조는 없어지고, 재기가 가르는지는 뮤테이션(크게 · 옅어지기만)으로 보였다 |
| 서버 준비 중 | `note` prop | 덮개 아래 작은 글씨(흰 알약 바탕) · 펴질 때 같이 사라짐 |
| 상한 | 준비 신호 없이 `capMs`(기본 15 초) | 그냥 편다 · `data-reason="cap"` |

표시는 펴지기가 시작될 때 씁니다. 읽기 · 쓰기는 모두 `try` 로 감싸, 저장소가 막혀 있어도 화면은 정상입니다.

### 상한 15 초의 까닭(잠정)

- 이 세션 컨테이너(GPU 없음 · 소프트웨어 WebGL)에서 시연 지도 idle 까지 걸린 시간은 chromium 약 2.3 ~ 3.7 초, webkit 약 2.8 ~ 8 초였습니다. 가장 느린 값의 두 배 가까이를 두었습니다.
- 15 초 넘게 구름만 보이면 사용자는 멈춘 것으로 봅니다. 본 프로젝트의 서버 재시작 직후(/api 503) 길이는 iPad 실기에서 잰 뒤 확정합니다.

## iPad(WebKit)에서 부드럽게

- **영상 덮개**: 움직임은 영상 재생이 그려 메인 스레드 애니메이션이 없습니다. 바탕 · 첫 장면 · 기다림을 걷는 것도 `opacity` 하나입니다.
- **동작 줄이기 덮개**: 구름 조각마다 레이어 하나(`will-change: transform, opacity`)에 CSS 애니메이션 하나씩 — 합성 단계에서 돌아, 메인 스레드가 지도 그리기로 막혀도 끊기지 않습니다.
- **쓰지 않은 것**: SVG 필터 · blur · backdrop-filter · mask · 화면 전체 Canvas · WebGL · 바깥 글꼴 · CDN. 앞 시안에서 쓰던 `stroke-dashoffset` 그리기와 mask 쓸기는 이번에 없앴습니다(메인 스레드 애니메이션이 하나도 없음).
- **진단 창(`?debug=1`)**: 펴지기 중 프레임 수 · 가장 긴 간격 · 50 ms 넘은 프레임 수 · 지도 idle · 준비 · 펴지기 시작 → 끝 · devicePixelRatio 를 보여 줍니다.
  - 시작 · 끝 시각은 `data-phase` 변화로 잽니다. 메인 스레드가 막혀 `requestAnimationFrame` 이 한 번도 안 돌아도 놓치지 않습니다(이 컨테이너의 webkit 에서 실제로 0 번이었음).
  - 진단 창에는 다음 한 줄을 적어 두었습니다.

> 프레임 간격은 메인 스레드 기준 — transform · opacity 펴지기는 합성 단계라 숫자가 나빠도 눈엔 부드러울 수 있음 · 판정은 눈이 먼저

## 지운 시험 · 까닭

| 지운 것 | 까닭 |
| --- | --- |
| 첫 장면 0.6 초 안에 선 그리기 완성(단위) | 선 그리기 장면이 없어짐 — 구름은 처음부터 덮은 채 시작 |
| 펴지기에 들어가도 그려 둔 선 · 채움이 남는다(e2e) | 멈춰 둘 그리기 애니메이션이 없어짐 |
| 잉크 덧그리기 · 빗금 차례(단위) | 같은 까닭 |
| 뮤테이션 「첫 구름 하나씩 차례로」 · 「commitStyles 로 되돌림」 | 대상 코드가 없어짐 |
| 첫 접속은 크게 벌어진다(「작게」 의 대조 · e2e) | 10-19 영상 방식 선택 — 첫 접속에 구름 조각이 없음. 대신 뮤테이션(줄인 펴짐 이동 × 0.5 · 크기 1.6 / 옅어지기만)을 「조금만 벌어지며」 가 잡음 |
| 시안 a · b · c: 펴지기 동안 애니메이션은 transform · opacity 뿐(e2e) | 시안 · PNG 첫 접속 덮개를 걷음. 동작 줄이기의 같은 확인은 「조금만 벌어지며」 시험에 남음 |
| 두 번째 짧은 판도 펴지기 동안 transform · opacity 뿐(e2e) | 두 번째도 영상(걷힘 영상만) — 움직이는 CSS 애니메이션이 없음 |
| 하늘 dense · sparse 빈틈 · 시안 b 「가운데 구름부터」(e2e 고리) | 배치 · 시안을 하나씩만 남김 — mid 하나 · 동작 줄이기에서 잼 |
